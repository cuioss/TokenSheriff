== Status

Accepted

== Context

An audit of `token-sheriff-client` found seventeen coverage gaps on the token-refresh path, none of
which could turn the build red. At the commit before the change the module reported BRANCH
502/591 = 0.8494; the refresh path accounted for 29 of those covered branches, and the module carried
exactly 29 branches of slack above the inherited `BUNDLE` rule's 0.80 floor. A total wipeout of
refresh-path coverage would land at 473/591 = 0.8003 — still green. The blind spot is structural:
moving the floor only moves which subset sizes go undetected.

A second constraint: `.github/workflows/maven.yml` delegates the Maven lane to an externally owned,
SHA-pinned reusable workflow, so this repository cannot pass a profile flag into CI. A gate that must
run in CI has to live in the module's always-active `<build><plugins>`.

== Decision

When a regression class is confined to a small, known subset of a larger unit, the gate's
*granularity* — not its threshold — decides whether the regression is detectable. The gate is a
`CLASS`-element JaCoCo `check` rule scoped by an explicit `<includes>` list to exactly the classes that
own the refresh path, bound in the always-active build, with floors set with real margin above the
scoped classes' measured coverage.

The finer granularity must also be *scoped*: applied module-wide, `CLASS` at 0.80 was red on six
unrelated classes, and `PACKAGE` at 0.80 was red on pre-existing debt; ratcheting the `BUNDLE` rule to
0.85 was flake-prone (two clean runs differed by two branches). A gate nobody has seen fail is not
known to work, so the rule's binding is proven by a negative control.

== Consequences

* A regression confined to the scoped classes is caught on the default lane, including CI, independent
  of unrelated headroom elsewhere in the module, with no CI workflow change.
* The scoped gate complements, and replaces neither of, the module-wide `-Pcoverage` baseline and the
  SonarCloud changed-line gate.
* The `<includes>` list is hand-maintained, and an entry matching no class reports success silently;
  `RefreshPathCoverageGuardTest` guards both drift directions, with a stated residual gap for a
  refresh-path class whose package or name prefix the list does not yet use.

The gate's mechanics, the guard's two legs and the division of labour with the other coverage
instruments are maintained in
xref:../developer/test-impl-mapping.adoc#refresh-path-coverage-gate[Test-to-Implementation Mapping § Refresh-path coverage gate].
