== Status

Accepted

== Context

A public, subclassable type with one overridable entry method sometimes needs to carry a new signal
through that method. Adding an overload that carries the signal, and switching the type's own callers
to prefer it, silently bypasses every subclass override of the original method: the subclass compiles,
throws nothing, and its override is dead code from that moment. The break surfaces only when a
consumer notices its override never fires — in this codebase, an integration test that hung waiting
for an overridden method the production path no longer called.

== Decision

A new signal on the outcome of a public, subclassable entry method is carried on the exception
hierarchy the method already throws, as a marker or accessor implemented by dedicated *subtypes* of the
documented thrown types, never by a preferred overload. Every internal caller keeps calling the one
original signature; a caller that needs the signal reads it back off the thrown exception. A carrier
that is not a subtype of a documented thrown type would itself break the thrown-type contract and is
not allowed.

Rejected: the preferred overload (the silent break above); off-band thread-local state (lost when a
caller hands the exchange to another thread); making the original overload `final` (a guaranteed
compile break for every legitimate override).

== Consequences

* The entry point stays singular, and every existing `catch` clause, `assertThrows` assertion and
  `@throws` contract stays valid. Further signals follow the same pattern.
* A caller that wants the signal must type-check or downcast the exception. The pattern needs an entry
  point that fails by exception, not by a sentinel return value.
* Nothing prevents the mistake structurally; the mitigation is review-time, through the pre-flight
  check in `AGENTS.md` § Code Standards (is the method overridable, does anything override it, test
  doubles included).

The carriers in the client engine are listed in
xref:../client/architecture.adoc#_extension_points[Client Architecture § Extension points].
