= Test-to-Implementation Mapping
:toc: left
:toclevels: 2
:toc-title: Table of Contents
:sectnums:

This document maps each production package of the four production modules to the test
classes that exercise it. It also lists the cross-cutting guards that check the code base
as a whole, and the integration-test specifications per feature area.

Use it to find where a behaviour is tested before you change it, and to see which test
class a new test belongs in. The mapping names test classes only; it makes no statement
about coverage figures.

Most test classes live in the same package as the production code they test, under
`src/test/java`. Where a test class sits in a different test package, its row names that
package. Where a production package has no test class of its own, the row says so.

=== Test infrastructure

The test package `validation.test` and its sub-packages hold the shared test infrastructure:
token generators, key material, tamper utilities and the MockWebServer dispatchers. Its own
tests check that infrastructure, not production code: `InMemoryKeyHandlingTest`,
`JwtTokenTamperingUtilReproductionTest`, `JwtTokenTamperingUtilTest`, `TestTokenHolderTest`,
`EndpointDispatchersTest` (`test.dispatcher`), `ClaimValueGeneratorTest`,
`TestTokenGeneratorsTest`, `TokenSecurityPropertiesTest` (`test.generator`) and
`TestTokenSourceProviderTest` (`test.junit`).

Fixtures that are not test classes: `BoundedBodyHandlerTestSupport` (`commons.transport`),
`DiscoveryGenerationDispatcher` (`validation.jwks.http`), `DpopProofValidatorSupport`
(`validation.dpop`), `JwksLoaderKeyIdsContractSupport` (`validation.jwks`) and
`JsonTypedIdentifierClaimFixture` (`validation.pipeline.validator`).

[#keeping-current]
== How to keep this current

Update this mapping in the same pull request that adds, moves, renames or splits a test
class. A test class that is not listed here, or a listed class that no longer exists, is a
defect in this document.
