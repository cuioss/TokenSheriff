### Layer 1 — Specified

### Layer 3 — Correct

- **L3-1 (minor, reported not staged).** The accept-loop bound: five back-to-back `SocketException`s from `accept()` with the socket open (for example "Too many open files" on a loaded host, no delay between attempts) end the thread silently with no log; clients still connect into the backlog and wait until their read timeout, so the symptom is a hang or a misleading timeout (`RawHttpServer:228-246`, re-read).
- **L3-2 (not shown by reading).** `ParserConfig.class.getClassLoader()` is the application loader in a flat classpath and the better choice in an isolating container, and a native image has one loader; but the same `DslJson` reads the client module's `@CompiledJson` types (`TokenResponse`, `ProviderMetadata`, `ParResponse`, `UserInfoResponse`, `TokenErrorResponse`), whose providers sit in the client jar's `META-INF/services`. Where the client jar is loaded by a child of the validation jar's loader, this loader would not see them while the context loader might. Whether Quarkus dev mode, fast-jar or native split the two jars is not shown (the leaf; not re-read).
- **Checked and sound:** `close()` (ordering, suppressed failures, interrupt flag restored, a second call repeats the steps; the thread is non-daemon so an unclosed instance keeps a forked JVM alive), the cause handling (no JDK message or raw header value chained or echoed on the new paths; the unwrap bound is 8 and the malformed walk 8, so at most 16), the new package-private constructor (no public API added).
