How to run the benchmarks locally and view the generated reports in a browser.

== Quick Start

[source,bash]
----
# 1. Run the benchmarks
./mvnw verify -pl benchmarking/benchmark-core -Pbenchmark              # library (JMH)
./mvnw verify -pl benchmarking/benchmark-integration-wrk -Pbenchmark   # WRK (requires Docker)

# 2. Serve the results (stays in the foreground)
cd benchmarking/scripts
./serve-reports.sh library        # or: ./serve-reports.sh wrk
----

Then open http://localhost:8080. For a faster library run, add `-Pbenchmark,quick` or `-Djmh.iterations=1 -Djmh.warmupIterations=1`.

Optional variations of step 2, run from the repository root:

[source,bash]
----
benchmarking/scripts/serve-reports.sh library 8081   # different port
benchmarking/scripts/serve-reports.sh stop           # stop running servers (from another terminal)
----

== What Is Served

`serve-reports.sh` serves the module's `target/benchmark-results/gh-pages-ready/` directory with `python3 -m http.server` (falling back to Python 2):

* `library` - `benchmarking/benchmark-core/target/benchmark-results/gh-pages-ready/`
* `wrk` - `benchmarking/benchmark-integration-wrk/target/benchmark-results/gh-pages-ready/`

The pages are `index.html` (latest run), `trends.html` (history) and, for the library benchmarks, `detailed.html`. The full content of the directory is described in link:../README.adoc#_generated_structure[Generated Structure]; it is the content the CI workflow deploys.

The pages load their data with JavaScript, which browsers block for `file://` URLs, so the reports must be served over HTTP. Any static server works, for example from the `gh-pages-ready/` directory:

[source,bash]
----
python3 -m http.server 8080
npx http-server -p 8080
----

== Troubleshooting

=== No Results Generated

* Check the Maven output: the benchmarks must have completed and the `benchmark` profile must have been active.
* `serve-reports.sh` reports a missing `gh-pages-ready/` directory with the command that creates it.

=== "Failed to fetch" Errors

* Open the reports through `http://localhost:8080`, not `file://`.
* Check that the server is still running and serves the `gh-pages-ready/` directory.

=== Port Already in Use

* Use another port: `benchmarking/scripts/serve-reports.sh library 8081` (from the repository root)
* Stop existing servers: `benchmarking/scripts/serve-reports.sh stop` (from the repository root)
