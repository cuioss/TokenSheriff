Performance testing infrastructure for JWT validation: JMH micro-benchmarks of the library and WRK load tests of the Quarkus integration, with generated reports, badges and trend data for GitHub Pages.

== Modules

|===
|Module |Purpose

|link:benchmarking-common/README.adoc[benchmarking-common]

|link:benchmark-core/README.adoc[benchmark-core]

|link:benchmark-integration-wrk/README.adoc[benchmark-integration-wrk]
|WRK-based HTTP load testing against the Quarkus integration (requires Docker)
|===

Module boundaries and code placement are defined in link:doc/Architecture.adoc[Architecture].

== Quick Start

[source,bash]
----
# Library micro-benchmarks
./mvnw verify -pl benchmarking/benchmark-core -Pbenchmark

# Library micro-benchmarks with JFR instrumentation
./mvnw verify -pl benchmarking/benchmark-core -Pbenchmark-jfr

# WRK load testing benchmarks (requires Docker, ports 10443 and 1443 free)
./mvnw verify -pl benchmarking/benchmark-integration-wrk -Pbenchmark

# View the results at http://localhost:8080
cd benchmarking/scripts
./serve-reports.sh library   # or: ./serve-reports.sh wrk
----

Profiles and parameters are listed in the module READMEs; viewing results locally is described in link:doc/local-testing.adoc[Local Testing Guide]. Java 21+ is required.

== Generated Structure

Each module writes its results to its own `target/benchmark-results/` (the JFR library run to `target/benchmark-jfr-results/`). The layout is defined by `OutputDirectoryStructure`:

[source]
----
target/benchmark-results/
├── gh-pages-ready/                  # Deployable to GitHub Pages
│   ├── index.html                   # Overview of the latest run
│   ├── trends.html                  # Historical trends
│   ├── detailed.html                # Detailed results (micro-benchmarks only)
│   ├── 404.html, robots.txt, sitemap.xml
│   ├── report-styles.css, data-loader.js
│   ├── badges/                      # shields.io endpoint JSON
│   │   ├── performance-badge.json   # integration-performance-badge.json for WRK
│   │   ├── trend-badge.json         # integration-trend-badge.json for WRK
│   │   └── last-run-badge.json
│   ├── data/
│   │   ├── benchmark-data.json      # Processed results read by the HTML pages
│   │   ├── original-jmh-result.json # Copy of the raw JMH result (micro-benchmarks)
│   │   └── *-server-metrics.json    # Prometheus metrics (WRK)
│   ├── api/
│   │   ├── latest.json              # Latest run summary
│   │   ├── benchmarks.json          # Benchmark results
│   │   └── status.json              # Status and last-run timestamp
│   └── history/                     # Archived runs for trend analysis (default location, see below)
├── prometheus/                      # Raw Prometheus metrics (WRK, not deployed)
└── wrk/                             # Raw WRK output (WRK, not deployed)
----

`HistoricalDataManager` archives the last 10 runs in the directory named by the `benchmark.history.dir` system property; without that property it uses `gh-pages-ready/history/`. Module-specific files outside this tree (raw JMH results, logs) are listed in the module READMEs.

== Scoring and Trends

Every run computes a performance score and letter grade from throughput and latency (link:doc/performance-scoring.adoc[Performance Scoring]) and compares the score with the archived runs to set the trend badge. There is no pass/fail quality gate: a run does not fail because of its score, and regressions show up in the trend badge and in `trends.html`.

== CI/CD Integration

The GitHub Actions benchmark workflow runs both benchmark modules, combines their `gh-pages-ready/` artifacts and deploys them to https://cuioss.github.io/TokenSheriff/benchmarks/. See link:doc/workflow.adoc[Benchmark Workflow].
