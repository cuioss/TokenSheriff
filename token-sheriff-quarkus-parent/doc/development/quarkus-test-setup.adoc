== Overview

Test framework configuration for the Token-Sheriff Quarkus extension, covering dependencies, logging, and test execution setup.

== Logging Configuration

Defined in `src/test/resources/logging.properties` in both runtime and deployment modules. Uses JUL API with JBoss LogManager, configures console output with readable format, and sets appropriate log levels to reduce noise.

== Maven Surefire Configuration

[source,xml]
----
<plugin>
    <artifactId>maven-surefire-plugin</artifactId>
    <configuration>
        <systemPropertyVariables>
            <java.util.logging.manager>org.jboss.logmanager.LogManager</java.util.logging.manager>
            <java.util.logging.config.file>${project.build.testOutputDirectory}/logging.properties</java.util.logging.config.file>
        </systemPropertyVariables>
    </configuration>
</plugin>
----

=== Fork Groups

`token-sheriff-quarkus-parent/pom.xml` configures surefire for every Quarkus module with `reuseForks=true` and two executions. Each execution runs its test classes in one reused JVM:

[cols="1,1,3", options="header"]
|===
|Execution |Tag filter |Test classes
|`default-test` |`<excludedGroups>quarkus-boot</excludedGroups>` |Plain test classes, which do not boot a Quarkus application
|`quarkus-boot-test` |`<groups>quarkus-boot</groups>` |Test classes that boot a Quarkus application
|===

A test class boots Quarkus when it is annotated `@QuarkusTest` or declares a `QuarkusExtensionTest` field. Such a class must carry `@Tag("quarkus-boot")` on the top-level class, and no other class may carry it. A plain class therefore never shares a JVM with a Quarkus application.

[source,java]
----
@QuarkusTest
@Tag("quarkus-boot")
class MyEndpointTest {
}
----

`SurefireForkGroupGuardTest` in `token-sheriff-validation-quarkus` enforces the rule. It reads the test sources of every Quarkus module and the surefire configuration of the parent pom, and fails when a class is in the wrong group. A build limited to a sibling module does not run the guard; the full build does.

The two executions run one after the other and write to the same JaCoCo data file.

=== Running a Selection with -Dtest

A `-Dtest=...` selection matches classes of one group only. With two executions the other one would run nothing, and surefire fails an execution whose selection matched nothing. The parent pom therefore has the profile `focused-test-selection`, which is active whenever the property `test` is set:

* `default-test` drops its tag filter and runs the selection, whatever group the classes belong to.
* `quarkus-boot-test` is skipped.

The pom does not set `failIfNoSpecifiedTests`, so surefire keeps its strict default: a selection that matches no class, for example a mistyped class name, fails the build. `SurefireForkGroupGuardTest` fails when the pom sets the parameter.

A selection that names plain classes and Quarkus-boot classes together runs them in one JVM. The separation of the two groups holds for runs without `-Dtest` only, which includes every CI run.

With `-pl <module> -am` the selection is also applied to the upstream modules, where it matches nothing and fails the build. Add `-Dsurefire.failIfNoSpecifiedTests=false` to such a run. The check is then off for the selected module as well, so a mistyped name is no longer reported.

== Test Framework Usage

=== QuarkusExtensionTest

[source,java]
----
@Tag("quarkus-boot")
@EnableTestLogger
class MyQuarkusTest {
    @RegisterExtension
    static final QuarkusExtensionTest unitTest = new QuarkusExtensionTest()
            .withEmptyApplication()
            .setLogRecordPredicate(log -> true);
}
----

=== WeldJunit5

The `weld-junit5` dependency is available for CDI-based unit testing. Tests use `@EnableTestLogger` for log verification and standard JUnit 5 patterns:

[source,java]
----
@EnableTestLogger
class MyCdiTest {
    // Use direct instantiation or manual CDI setup with weld-junit5
    // No @EnableAutoWeld - this project uses weld-junit5, not weld-junit5-auto
}
----

== Framework Selection

* **QuarkusExtensionTest**: Extension registration, Quarkus subsystems, ConfigMapping (tagged `quarkus-boot`, see <<Fork Groups>>)
* **WeldJunit5**: CDI beans in isolation, dependency injection testing
* **Plain JUnit5**: Pure Java code, utilities, fastest execution

See xref:../configuration/testing-configuration.adoc[Testing Configuration] for JWT-specific testing patterns.
